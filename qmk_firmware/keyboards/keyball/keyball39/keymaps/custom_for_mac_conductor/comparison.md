# custom_for_macとの比較と移植上の制約

2026-10-22。キー割り当てはConductor、構造とハードウェア設定は既存Keyballを優先する。

## 既存Keyballへ寄せた部分

| 対象 | 採用内容 |
|---|---|
| レイヤーの並び | 基本→数字→機能→Emacs→AML→スクロールを維持。QWERTY/空き層を省き番号を圧縮 |
| レイアウト記述 | LAYOUT_universal、5+5列、最下段6+6枠の元の形式へ統一 |
| キー表記 | XXXXXXX / _______ / LCAGなど、元のキーマップの表記を使用 |
| AML | QMK標準処理、元のキー割り当て、400ms、初期ONを維持。対象層番号のみ変更 |
| CPI・スクロール | CPI・保存設定・反転なしを維持。自由モードは自動軸ロック、横感度は1/2へ変更 |
| タップ判定 | 全体の200msはQMK既定を使用し、同値の重複定義を除去 |
| OLED・VIA | 元の機能設定を維持。Comboとキーマップ専用のポインタ加速ソースを追加 |

## Conductorを優先した部分

- Macの文字・修飾キー・親指キー・数字記号・機能・Emacs配列。
- LANG2の長押しは元の左Altではなく左GUI。
- 無効/透過の区別を含めて移植。元のEmacs層にあったCtrl+T/Y/O等は追加しない。
- スクロール層はConductorのショートカットを優先。Keyballの調整キーはSETTINGSへ分離。
- 左/中/右クリックComboとR+YのジェスチャーCombo。Boot/BluetoothのComboは除外。
- Caps Lockを削除し、ボール部分の3枠は無効化。
- GESTUREのキー割り当てをボール処理から参照。
- 通常ポインタに最大1.4倍の速度依存加速を追加。閾値4、幅16、低速時1倍。
  現在フレームのX/Yから倍率を決定し、スクロールとジェスチャーには適用しない。
- スクロールは最近の動きで軸を選択し、同程度なら縦を優先。
  反対軸が2倍優勢なら切り替え、200ms無動作で解除。横感度を1/2へ変更。
  初期軸は縦とし、微小な縦入力を開始閾値で捨てずに蓄積する。

## 修正済みの問題

| 問題 | 対応 |
|---|---|
| 前版ではレイヤーのキーを変更してもジェスチャー出力が固定 | keymap_key_to_keycodeでGESTURE層を参照 |
| 一時スクロール解除で、押しているSCROLL層のスクロールまで停止 | キーの押下状態とレイヤー状態の所有者を分け、Keyball処理後に再計算 |
| AMLのレイヤー変化で、一時スクロールが解除される | 押されているSCRL_MO/MOV/MOHを保持して再計算 |
| 元の層順を復元すると、AMLが数字・機能・Emacs層を覆う | 明示的な操作層が有効な間はQMKのAPIでAMLを除去。AMLの設定自体は維持 |
| レイヤーキー等をジェスチャーへ割り当てると不正なHIDコードを送る可能性 | 通常/修飾キー付きコード以外を拒否 |
| ゆっくりした縦スクロールが開始閾値に届かず捨てられる | 初期軸を縦にして微小入力を蓄積。閾値は軸切り替えにのみ使用 |

## 未定義・ZMK/QMK差分の確認結果

### ビルドで確認済み

QMK 0.22.14でコンパイル・リンク成功。最終ELFをavr-nmで確認し、未解決シンボルはない。
LT/MT/MO、KC_LNG1/2、KC_BTN1～5、VIA、Combo、AMLと各フックはこの版に定義されている。
KC_BTN3はこの版では8bit内の基本コードであり、LT(SCROLL, KC_BTN3)へ格納できる。
異なるQMK版への追従時は、マウスコードの範囲とフックAPIを再確認する。

### 意図的に対応しない機能

Bluetooth接続・プロファイル・切断、Conductor Studio RPC、精密操作、Windowsマクロは含めない。
加速はビルド時設定として実装し、StudioやEEPROMからの加速設定変更は含めない。
Conductorのsensor-bindingsも移植しない。Keyballのボールはエンコーダーとして扱わない。
GESTUREへMO/MT/LTやKeyball独自キーを割り当てても、ボールからは実行しない（物理キーの通常処理とは別）。

### 実機確認が必要な点

1. **タップ/長押し判定**: ZMKのtap-preferred/hold-preferredとQMKの判定は完全同一ではない。
   200msとキー別設定で近づけているが、ロール入力、連打、中クリック長押し、ドラッグは実機確認が必要。
2. **Combo**: QMKは基本層を参照して物理位置を維持する。VIAで基本層のT/N/S/H/R/Yを変更すると
   Comboの認識条件も変わるため、キー変更時には確認が必要。複数のクリックComboは構成キーが重なる。
3. **ジェスチャー感度**: ZMKは入力プロセッサ内、QMKはKeyballが変換したレポートで判定する。
   閾値等の数値を合わせても物理的な移動量は一致しない。CPIはKeyballの値を維持している。
4. **軸ロック**: 自由モードへConductor方式を移植し、Keyballの縦/横固定も維持する。
   Conductorの1/2スケーリング後の閾値6に対し、Keyballでは生の移動量で閾値12を使う。
   微小入力を失わないように初期軸は縦に変更し、この閾値は軸切り替えだけに使用する。
   センサーとCPIが異なるため、物理的な開始感度は実機で確認する。
5. **VIA保存配列**: EEPROM内の旧キー配列が新しいレイヤー番号を上書きすると、違う層へ入る等の問題が出る。
   キー配列を新構成へ更新する。CPI等の設定全消去とは区別する。
6. **Mac側の割り当て**: LANG1/2のIME動作、Ctrl+Alt+Command系やControl+矢印の効果はMac側設定に依存する。
   ファームウェアはConductorと同じキーコードを送る。
7. **対象ハードウェア**: 右ボール39キー構成を前提とする。左ボールや別MCU向けの動作は未検証。
8. **容量**: 微小スクロール修正後はFlash残り72 bytes。既存機能の削減なしで収まった。
   今後の機能追加には再計測が必要。実機のスタック余裕と長時間動作は未測定。
