# Keyball39: custom_for_mac_conductor

`custom_for_mac` の構造を基に、ConductorのMac用キー割り当てを移植したキーマップです。
右トラックボール構成を対象とし、元の `custom_for_mac` と共有ドライバーは変更しません。
Conductorの参照元は `8a1cff7` の `config/monokey.keymap` です。
差分の採否、修正済みの問題、残る制約は [comparison.md](comparison.md) にまとめています。

## レイヤー構成

既存Keyballの相対順序「基本 → 数字 → 機能 → Emacs → AML → スクロール」を維持します。
QWERTY補助層と空き層を省き、設定・ジェスチャーを後ろに追加して8層に収めます。
元のレイヤー番号そのものは維持せず、参照先をすべて詰め直しています。

| 新番号 | 名前 | custom_for_mac | Conductor |
|---|---|---|---|
| 0 | MAC | 0 | 0 |
| 1 | NUM | 2 | 2 |
| 2 | FN | 3 | 7 |
| 3 | EMACS | 4 | 9 |
| 4 | AML | 6 | 移植しない（QMKのAMLを維持） |
| 5 | SCROLL | 7 | 5 |
| 6 | SETTINGS | 7の調整キーを分離 | 11の用途をKeyball向けに変更 |
| 7 | GESTURE | 追加 | 13 |

既存と同じ `LAYOUT_universal`、8bitレイヤー状態、VIA/Remapの8レイヤー設定を使います。
右ボール部分の実在しない3キーは `KC_NO` とし、物理39キーを使います。
Caps Lockの再配置は行いません。

## 主な操作

- E長押し: EMACS。Space長押し: NUM。LANG1長押し: SCROLL。Enter長押し: FN。
- LANG2長押し: Conductorに合わせた左GUI。文字配列・MacショートカットもConductorを優先。
- T+N: 左クリック。N+S: タップで中クリック、長押しでSCROLL。S+H: 右クリック。
- R+Yを押している間: GESTURE。
- SCROLL中にSpaceの位置を押す: 押している間SETTINGS。
- SETTINGS上段左: CPI -100、CPI +100、スクロール除数+、除数-、設定保存。
- SETTINGS上段右: 自動軸ロック（旧・自由スクロール）、縦固定、横固定。
- SETTINGS中段右端: AML ON/OFF。下段左: AML時間 -50/+50ms。
- Function層: Control+Shift+Command+4でスクショをクリップボードへ保存。

CPI、スクロール除数・反転設定、AMLの400ms、OLED、VIAは既存設定を維持します。
自由スクロールはConductor方式の自動軸ロックに変更し、縦固定・横固定は維持します。
通常の複合キーの200ms判定はQMK 0.22.14の既定値を使用します。
中クリック/スクロールだけはキー別の長押し優先、quick-tap無効を設定しています。
クリックComboは25ms、ジェスチャーComboは50msです。

AMLがNUM/FN/EMACSより上位になる点は元の構造に合わせますが、明示的な操作層が有効な間は
QMKの `remove_auto_mouse_layer` を使ってAMLを重ねません。キーがAMLに隠れることを防ぎます。
AMLのON/OFF状態、400ms、キー配列は維持します。

## ジェスチャー

| ボール方向 | 既定の送信キー | 参照するGESTURE層の位置 |
|---|---|---|
| 上 | Control+Down | 右上段、左から3番目 |
| 下 | Control+Up | 右下段（文字段）、左から3番目 |
| 左 | Control+Right | 右中段、左から2番目 |
| 右 | Control+Left | 右中段、左から4番目 |

出力はGESTURE層を参照するため、VIAでそのキーを変更すればボール操作にも反映されます。
通常キーと修飾キー付きショートカットに対応し、レイヤーキー・Tap-Hold・Keyball独自キーは送信しません。
閾値120、判定窓180ms、再発火待ち220ms、押下時間30msです。
押下解除は非同期で、ジェスチャー中はポインタ加速を通しません。

## ポインタ加速

通常のポインタ移動は、少ない移動量では1倍、素早く動かすと最大1.4倍に加速します。
Conductorの直線的な加速カーブを基に、Keyballの既定8ms報告ごとの
`abs(X) + abs(Y)` が4以下なら1倍、20以上なら1.4倍、その間を連続的に変化させます。
例として移動量8では1.1倍、12では1.2倍です。総移動距離の蓄積による加速ではありません。

`config.h` の `CONDUCTOR_POINTER_ACCEL_MAX_MILLI` が最大倍率（1400 = 1.4倍）、
`THRESHOLD` が開始閾値、`RANGE` が最大倍率までの追加移動量です。
`CONDUCTOR_POINTER_ACCEL_ENABLE` を0にすると元のポインタ変換に戻ります。
今回の設定はビルド時に指定し、Studio RPCやEEPROMへの加速設定保存は追加しません。
報告間隔やCPIを変更した場合は閾値も調整してください。

キーマップ専用の `pointer_accel.c` とweakフックの差し替えで実装し、共有ドライバーは変更しません。
左右のボールごとに小数端数を保持し、X/Yを同じ倍率で処理します。
高速移動でHIDの±127を超える場合は、両軸を同じ比率で縮小して方向を保ちます。
上限超過分を後のフレームに送り続ける動作は行いません。
スクロール・ジェスチャー中は加速を外し、切り替え時に端数をリセットします。
加速はCPI、スクロール変換、ジェスチャー閾値には適用しません。

Conductor側はイベントがX/Y別に届くため前フレームの倍率を使いますが、
QMK側はX/Yを同時に受け取れるので現在のフレームから倍率を計算します。
センサーとCPIも異なるため、Conductorと完全に同じ体感になることは保証しません。

## スクロールの軸ロック

Conductorの `zip_scroll_axis_lock` と横感度1/2の設定を移植しました。
自由スクロール設定（`SSNP_FRE` / `SCRL_MO`）では、最近の動きから縦か横の一方を選び、
両軸を同時に出力しません。縦固定・横固定キーは従来通り、指定軸を優先します。

- 最初から縦を選び、微小な縦入力も既存の除数で蓄積します。開始時の閾値待ちはありません。
- ロック後は、反対軸が最近の動きで2倍以上優勢になると切り替えます。
  横へ意図的に動かせば、縦ロック中でも横スクロールできます。
- 200ms動きがなければ解除し、次の操作で軸を選び直します。
- 横スクロール感度は従来の1/2。縦の除数は維持します。
- 抑えた軸の移動量は捨て、後から横スクロールが漏れないようにします。
  採用した軸の小数端数は保持するため、低速時の量は失いません。

Conductorは1/2スケーリング後に閾値6で判定するため、Keyballでは除数適用前の
生の移動量を閾値12として軸の切り替えを判定します。縦の入力開始には適用しません。
`CONDUCTOR_SCROLL_ACTIVATE_THRESHOLD` と
`CONDUCTOR_SCROLL_RELEASE_MS` を `config.h` で調整できます。
縦横の蓄積は報告ごとに約25%減衰し、センサー/CPIの違いによる体感差は実機で確認します。
横感度1/2は固定の縦/横モードでも適用されます。ポインタ加速とジェスチャーには影響しません。

実装はキーマップ専用の `scroll_axis.c` とスクロール用weakフックの差し替えです。
左右の状態・端数は独立し、モード/除数変更時にリセットします。共通ライブラリーは変更しません。
参照したZMK実装は `pite1222/zmk` の `a62d5ee7` にある
`app/src/pointing/input_processor_axis_lock.c` と `app/dts/input/processors/axis_lock.dtsi`、
Conductorの `monokey_R.overlay` です。

Windows、QWERTY補助層、Conductor版AML、Caps Lock、ブートローダーCombo、Bluetooth操作・
マクロ、精密操作、Conductor側のCPI・高解像度スクロールHID・Studioのスクロール倍率設定は含めません。

## ビルド・検証

```sh
qmk compile -kb keyball/keyball39 -km custom_for_mac_conductor
```

GitHub Actionsの手動ビルドではkeyboard=`keyball39`、keymap=`custom_for_mac_conductor`を指定します。
既存の自動ビルドmatrixは変更していません。

2026-10-21、QMK 0.22.14 / AVR GCC 8.5.0で確認:

- ビルド・リンク成功。未解決の未定義シンボルなし。
- Flash: 27,250 / 28,672 bytes（残り1,422 bytes）。
- 静的RAM: .data 286 + .bss 1,038 = 1,324 bytes（スタック等を除く）。
- 全8層のレイアウト引数、主要な配列・参照先・除外項目を検査。
- ホスト上でジェスチャーの方向・閾値・タイムアウト・クールダウン・非同期解除・タイマー周回、
  VIA出力変更、不正な出力キーの拒否、一時スクロール解除、AMLと手動層の優先関係を検査。
- 実機書き込み・打鍵・Comboのタイミング・ドラッグは未検証。

2026-10-22、最大1.4倍のポインタ加速を追加して同じ環境で再確認:

- クリーンビルド・リンク・HEX生成成功。Flash 28,098 / 28,672 bytes（空き574 bytes）。
- 加速追加前との差はFlash +848 bytes、静的RAM +9 bytes（合計1,333 bytes）。
- 容量内に収まったため、OLED・VIA・Combo等の既存機能は削減していません。
- ホストのASan/UBSan付きテストで加速カーブ、端数保持、左右独立、方向対称性、
  最大入力、飽和、OFF/バイパス時の全16bit入力を確認。
- キーマップの実処理を使ったホスト検証で、軸変換・左側反転・ボタン保持・
  スクロール/ジェスチャー時のバイパスと、既存ジェスチャー/AML/スクロール所有権を確認。
- 実機への書き込みとポインタの体感確認は未実施。

同日、Conductor方式のスクロール軸ロックと横感度1/2を追加:

- Flash 28,630 / 28,672 bytes（空き42 bytes）、静的RAM 1,357 bytes。
- 最初は58 bytes超過したため、状態初期化の共通化と整数演算の整理で100 bytes削減。
  最大1.4倍の加速計算は等価な分数へ約分し、10万報告の比較で旧計算と出力一致を確認。
- OLED、VIA、全8層、Combo、ジェスチャー、ポインタ加速は削減していません。
- ASan/UBSan付きテストで、初期横漏れ抑制、縦優先、横への意図的な切り替え、200ms解除、
  タイマー周回、縦/横固定、横の端数保持、除数変更、左右独立、最大入力を確認。
- キーマップの実処理を使って軸変換、左側反転、ボタン保持と既存機能の回帰を確認。
- 残り容量が小さいため、今後の設定変更・機能追加後もサイズチェックが必要です。

微小スクロールの修正後はFlash 28,600 / 28,672 bytes（空き72 bytes）。
ポインタ加速は当初からスクロールと別経路で、反応しにくさの原因は未決定中の軸ロック閾値でした。
初期軸を縦として入力を捨てないようにし、8回の微小入力が通常の1ノッチになること、
負方向・200ms停止後の小入力・斜めの揺れもテストで確認しています。

加速・スクロールのホストテストはキーマップのディレクトリから実行できます:

```sh
sh tests/run.sh
```

新番号は旧VIA配列・前版の配列と互換ではありません。旧キー配列が残る場合は新配列へ更新してください。
CPI等を残す場合、キー配列の更新とKeyball設定全体の初期化を区別してください。
